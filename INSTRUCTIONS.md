## 1. Problem & audience
A blank `README.md` is where projects go to die. Writing badges, a table of contents, install/usage sections, and a license blurb by hand is boring and error-prone.

**Audience:** OSS maintainers, hackathon teams, anyone bootstrapping a repo who wants a professional README without effort.

## 2. Why it earns stars
- README-generators are a **perennial trending category** on GitHub.
- Meta-appeal: the tool's *own* README is the best possible demo.
- Instant gratification — a polished README from a few prompts.

## 3. Scope
**MVP**
- `readmine` runs an interactive wizard (`readline`), pre-filled by reading `package.json` (name, description, license, bin, scripts, repo URL).
- Generates `README.md` with: title, badges, description, install, usage, scripts table, contributing, license.
- Detects package manager from lockfile (npm/pnpm/yarn/bun) for install commands.
- Writes to `README.md` (refuse to overwrite unless `--force`; offer `README.generated.md`).

**Stretch**
- `--yes` non-interactive mode (pure inference, no prompts).
- Template presets: `lib`, `cli`, `app`, `minimal` (`--template cli`).
- Auto table-of-contents from generated headings.
- Badge auto-detection: npm version, CI workflow, license, node engine.
- Detect language/ecosystem beyond Node later (pyproject.toml, Cargo.toml) — stretch only.

**Non-goals**
- No AI/network calls in MVP (keep it deterministic + offline + zero-dep). No HTML output.

## 4. Tech & constraints
- Node **>= 18**, ESM, **zero runtime deps**.
- `node:fs`, `node:path`, `node:readline/promises` only.
- Entry `bin/readmine.mjs`.

## 5. CLI / UX design
```
Usage: readmine [options]

Options:
  --yes            Non-interactive; infer everything, no prompts
  --template <t>   lib | cli | app | minimal   (default: auto)
  --out <file>     Output path (default: README.md)
  --force          Overwrite existing README.md
  -h, --help
  -v, --version
```

Example:
```
$ npx readmine
Detected: cli project "portkill" (MIT, npm)
Project tagline: › Kill whatever's on a port
Include badges? (Y/n) › Y
Add a Contributing section? (Y/n) › Y
✓ wrote README.md (78 lines) — preview it and tweak away
```

## 6. Architecture & file layout
```
readmine/
  bin/readmine.mjs
  src/detect.mjs      # read package.json, lockfiles, infer type/pm/badges
  src/prompt.mjs      # readline wizard w/ defaults
  src/render.mjs      # pure: (answers) -> markdown string
  src/templates/      # lib.mjs, cli.mjs, app.mjs, minimal.mjs (string builders)
  src/args.mjs
  test/render.test.mjs
  test/detect.test.mjs
  package.json
  README.md
  LICENSE
  CONTRIBUTING.md
  .github/workflows/ci.yml
  .gitignore
```

## 7. Implementation steps
1. Scaffold package.json/bin/license/gitignore.
2. `detect.mjs`: read `package.json` safely; infer type (bin→cli, main/exports→lib, else app); detect PM from `package-lock.json`/`pnpm-lock.yaml`/`yarn.lock`/`bun.lockb`; parse repo URL for badge slugs. Pure + tested.
3. `render.mjs`: pure function `render(answers) -> string`. **This is the heart — keep it pure and heavily unit-tested.**
4. `templates/*`: per-type section ordering.
5. `prompt.mjs`: wizard with detected defaults; skip when `--yes`.
6. `args.mjs`; wire `bin` (detect → prompt/infer → render → write with overwrite guard).
7. Tests + CI + README (generate readmine's own README **with readmine** — dogfood it).

## 8. Edge cases & safety
- No `package.json` → still work with sensible prompts; don't crash.
- Existing `README.md` → never overwrite silently; require `--force` or write to `README.generated.md`.
- Malformed `package.json` → catch, warn, continue with prompts.
- Sanitize interpolated values into markdown (avoid breaking code fences / badge URLs).
- Only reads within the project dir; writes exactly one file.

## 9. Testing plan (`node --test`)
- `render` snapshot: given a fixed answers object, output contains expected sections/badges in order.
- `detect`: fixtures for cli/lib/app; each lockfile → correct install command.
- Overwrite guard returns the alternate path when README exists and no `--force`.
